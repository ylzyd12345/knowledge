# Obsidian 知识库文章生成规则

> 版本：v1.0  
> 适用范围：`wiki/java/` 下按 `wiki/java/目录.md` 大纲批量生成的百科全书式笔记  
> 样例参考：`wiki/java/第一阶段：Java 基础入门/Java概述.md`

---

## 1. 路径与目录结构

### 1.1 知识库根路径

```
D:\work\personal\知识库\知识库\wiki
```

### 1.2 大纲映射规则

| 大纲层级 | 映射目标 | 示例 |
|----------|----------|------|
| `## 第一阶段：…` | 文件夹 | `java/第一阶段：Java 基础入门/` |
| `### [[概念名]]` | 同名 `.md` 文件 | `Java概述.md` |
| 子 bullet | 写入该文章的写作要点，不单独建文件 | — |

### 1.3 文件名约定

- 与大纲 `[[概念名]]` **完全一致**（含中文、括号、全角符号）。
- 示例：`面向对象编程（OOP）.md`、`垃圾回收（GC）.md`、`IO流.md`。
- 不使用空格替代符号，不自行简写。

### 1.4 主索引

- 路径：`wiki/Index.md`（wiki 根目录，非 `java/` 下）。
- 内容：按学习路径列出全部文章 + 一句话摘要。
- 摘要来源：以 `wiki/java/目录.md` 末尾 index 表为准，与每篇 frontmatter `summary` 及文首 blockquote 保持一致。

### 1.5 大纲源文件

- 结构定义：`wiki/java/目录.md`
- 各章 bullet 为**写作契约**的补充说明；index 表为**摘要契约**的权威来源。

## 2. 文章结构（固定板块）

每篇文章包含以下板块，使用 `##` 二级标题：

| 顺序 | 板块 | 说明 |
|------|------|------|
| 1 | 文首定位段 | 紧接 blockquote 后，1～3 句说明本文边界与读者收获 |
| 2 | 概念定义 | 清晰定义概念，必要时用表格归纳 |
| 3 | 核心原理 | 底层工作原理；深度随文章类型调整 |
| 4 | 实际应用 | 真实场景、配置或代码示例 |
| 5 | 源码分析 | JDK 或著名框架源码；无合适源码时写「典型实现思路」并标注 |
| 6 | 面试常见题目 | 附简要参考答案 |
| 7 | 思维发散 | 拓展问题或概念关联 |
| 8 | 相关概念（待扩展） | 纯文本列表，不用 wiki 链接 |

**不单独增加**「相关概念」以外的附录；子主题在核心原理下用 `###` 展开。

---

## 3. Frontmatter 规范

每篇文章顶部 YAML：

```yaml
---
phase: 第一阶段：Java 基础入门    # 与大纲 ## 标题一致（不含「##」）
type: 地图型                      # 地图型 | 机制型 | 工具型 | 框架型
summary: 一句话摘要               # 与 Index 表完全一致
related:                          # 纯文本，后续可批量转 [[链接]]
  - 概念名A
  - 概念名B
---
```

### 3.1 文首格式

```markdown
# 概念名

> 一句话摘要（与 summary 一致）

本文……（定位段：本文解决什么问题、不展开什么、与哪些专题的边界）
```

## 4. 文章类型与深度

不同类型**板块权重与篇幅不同**，禁止 44 篇同一深度。

### 4.1 类型定义

| 类型 | 适用场景 | 字数参考 | 板块权重 |
|------|----------|----------|----------|
| **地图型** | 总览、导论、体系介绍 | 1500～2500 | 概念 + 全景原理 + 应用；源码轻；面试偏「地图题」 |
| **机制型** | 语言机制、JVM、并发、底层原理 | 3000～5000 | 核心原理 + 源码 + 面试加重 |
| **工具型** | API 类、工程工具、使用指南 | 2000～3500 | 实际应用 + 示例/配置；源码可省略或极简 |
| **框架型** | Spring 等框架与生态 | 2500～4000 | 应用 + 架构原理；源码看入口类即可 |

### 4.2 代码示例规范

| 类型 | 代码数量 |
|------|----------|
| 地图型 | 1 个最小可运行或示意示例 |
| 机制型 | 1 个演示原理的示例 + 可选 1 段源码片段 |
| 工具型 | 1～2 个实用示例（API 调用 / 配置片段） |
| 框架型 | 注解 / YAML / 配置类为主 |

## 5. 链接策略（当前阶段）

### 5.1 正文

- **不使用** Obsidian `[[wiki 链接]]`。
- 提及其他概念时用**纯文本**（如「详见垃圾回收专题」）。

### 5.2 相关概念（待扩展）

- 文末独立小节，**纯文本列表**：概念名 + 一句说明。
- 来源：大纲中该章的「相关概念」bullet + 正文自然关联项。
- 同步写入 frontmatter `related` 数组。

### 5.3 后续扩展（暂不执行）

- 各专题写完后，将 `related` 与「相关概念（待扩展）」批量转为 `[[链接]]`。
- 内文链接在内容丰富后再补，避免大量未解析链接。

## 6. 边界与去重

### 6.1 地图型文章

- 只建立全景，每个子主题 **1～2 段 + 必要时一张流程图/表格**。
- 文首或原理节声明「本篇不展开：……」。
- 不抢占机制型/框架型专题篇幅。

### 6.2 跨文章去重

- 同一机制（如 synchronized）在多篇出现时：概述篇只点到为止，专题篇写透。
- JDK/JRE/JVM 细节以「JDK与JRE」或「Java概述」之一为主，其余引用一句即可。

### 6.3 源码分析门槛

- 优先 JDK 源码（`java.*`、`javax.*`、`sun.*` 等）。
- 框架型可选 Spring、MyBatis 等入口类或核心接口。
- 无合适源码时：标题可写「典型实现思路」，说明设计模式或执行路径，不虚构行号。

## 7. 面试题规范

| 类型 | 题量 | 难度分布 |
|------|------|----------|
| 地图型 | 5～6 道 | 以基础为主，最多 1 道进阶 |
| 机制型 | 6～10 道 | 基础 + 进阶，可含 1～2 道高频深挖 |
| 工具型 | 4～6 道 | 使用场景与易错点 |
| 框架型 | 5～8 道 | 原理 + 实战配置 |

- 每题须附**简要参考答案**（3～5 句），不只列题目。
- 进阶题不得超出本文边界；超出则标「参见 ×× 专题」。

## 8. 生成工作流

### 8.1 单篇流程

```
读取目录.md（摘要 + bullet）
    → 确定 type 与字数区间
    → 内部迭代 3 轮（见 评分标准.md）
    → 仅输出综合分最高版本
    → 写入目标路径
    → 记录评分到 output/生成日志.md（可选）
```

### 8.2 内部三轮迭代

| 轮次 | 目标 |
|------|------|
| 第 1 轮 | 骨架：frontmatter、八大板块、覆盖大纲要点 |
| 第 2 轮 | 边界：删超纲内容、补缺失契约项、调整类型深度 |
| 第 3 轮 | 打磨：面试答案、代码可运行性、表格与流程、去冗余 |

### 8.3 批量顺序

- 按 `目录.md` 阶段顺序生成，减少前后引用不一致。
- 已存在文件：**按本规则全文覆盖更新**（用户确认批量后执行）。

### 8.4 已确认样例

- `wiki/java/第一阶段：Java 基础入门/Java概述.md`（综合分 8.7，作为地图型标杆）

## 9. 禁止项

- 正文使用 `[[wiki链接]]`（当前阶段）。
- 为未在大纲 index 表中的概念单独建 stub 笔记。
- 虚构源码行号或捏造不存在的类名/方法名。
- 所有文章同一篇幅、同一深度。
- 面试题只列题目不写答案。
- 在地图型文章中展开 GC 算法、AQS、Spring 源码等专题级内容。
