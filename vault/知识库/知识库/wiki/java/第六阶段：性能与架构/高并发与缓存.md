# 高并发与缓存

> 本地/分布式缓存及缓存问题处理。

本文介绍缓存架构与经典问题解决方案。Redis 深入运维见数据存储专题；数据库优化见数据库专题。

---

## 概念定义

**缓存**将热点数据放在更快介质（内存）以减少 DB 压力、降低延迟。分为：

| 类型 | 示例 | 特点 |
|------|------|------|
| 本地缓存 | Caffeine、Guava Cache | 快、不跨节点一致 |
| 分布式缓存 | Redis、Memcached | 共享、需网络 |

---

## 核心原理

### 1. 缓存模式

- **Cache-Aside**：应用先读缓存，miss 读 DB 再写缓存
- **Read/Write Through**：缓存层同步写 DB
- **Write Behind**：异步写 DB

### 2. 三大经典问题

| 问题 | 现象 | 常见方案 |
|------|------|----------|
| **穿透** | 查不存在 key，直击 DB | 布隆过滤器、空值缓存 |
| **击穿** | 热点 key 过期瞬间并发打 DB | 互斥锁、逻辑过期 |
| **雪崩** | 大量 key 同时过期或缓存宕机 | 过期时间加随机、多级缓存、集群高可用 |

### 3. Caffeine 本地缓存

```java
Cache<String, User> cache = Caffeine.newBuilder()
    .maximumSize(10_000)
    .expireAfterWrite(Duration.ofMinutes(10))
    .build();
User u = cache.get(key, k -> loadFromDb(k));
```

W-TinyLFU 驱逐策略，高命中率。

### 4. Redis 分布式缓存

String、Hash、Set、ZSet；持久化 RDB/AOF；集群分片与哨兵高可用。

### 5. 一致性

延迟双删、Canal 订阅 binlog 更新缓存、设置合理 TTL 接受短暂不一致。

---

## 实际应用

```java
// 互斥锁防击穿（Redis）
String lockKey = "lock:" + key;
if (redis.set(lockKey, "1", "NX", "EX", 10)) {
    try {
        data = db.load(key);
        redis.set(key, data, ttl);
    } finally {
        redis.del(lockKey);
    }
}
```

多级缓存：Caffeine（L1）+ Redis（L2）+ DB。

---

## 源码分析

Caffeine 基于 Window TinyLFU 维护访问频率 sketches，在 `BoundedLocalCache` 中驱逐低频率条目。

Redis 单线程命令处理（6.0 多 IO 线程读）保证原子性，避免锁竞争。

## 面试常见题目

**1. 缓存穿透、击穿、雪崩？**

见上表。

**2. 如何保证缓存与 DB 一致？**

双删、MQ/binlog 异步更新、短 TTL。

**3. 本地缓存和 Redis 如何配合？**

多级缓存；注意本地缓存过期与广播刷新。

**4. 热点 key 问题？**

本地缓存、拆分 key、读写分离、预热。

**5. 分布式锁 Redis 实现注意？**

`SET NX EX`、Lua 原子释放、Redisson watchdog 续期。
