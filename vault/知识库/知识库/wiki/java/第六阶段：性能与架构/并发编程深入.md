# 并发编程深入

> AQS、锁优化、Fork/Join 并发框架。

本文深入 AQS、锁优化与 Fork/Join。基础同步见多线程与并发；线程池 Worker 亦基于 AQS。

---

## 概念定义

**并发编程深入**涵盖 JVM 锁优化、JUC 抽象队列同步器（AQS）及分治并行框架，是理解 `ReentrantLock`、`Semaphore`、`CountDownLatch` 与 `ForkJoinPool` 的基础。

---

## 核心原理

### 1. 锁优化（HotSpot）

| 状态 | 说明 |
|------|------|
| 偏向锁 | 无竞争时 CAS 贴线程 ID |
| 轻量级锁 | CAS 竞争锁记录 |
| 重量级锁 | 膨胀为 monitor，阻塞 |

锁升级路径：偏向 → 轻量 → 重量（不可逆升级方向）。`-XX:-UseBiasedLocking` 可关闭偏向锁。

### 2. AQS

`AbstractQueuedSynchronizer`：volatile `state` + CLH 双向队列。  
子类实现 `tryAcquire`/`tryRelease`；`ReentrantLock`、`Semaphore` 等均基于 AQS。

```java
// 概念：state=1 表示锁被占用
public void lock() {
    acquire(1);
}
```

### 3. Fork/Join

分治任务递归拆分，`ForkJoinPool` work-stealing：空闲线程从其他队列尾部偷任务。

```java
ForkJoinPool pool = ForkJoinPool.commonPool();
pool.invoke(new RecursiveTask<Integer>() {
    protected Integer compute() { /* split */ }
});
```

`parallelStream` 默认使用 common pool。

### 4. StampedLock

乐观读 `tryOptimisticRead`，写锁不阻塞读（适合读多写少，实现复杂）。

### 5. LongAdder

高并发计数，分段 Cell 降低 CAS 竞争，优于 `AtomicLong` 热点场景。

---

## 实际应用

```java
LongAdder counter = new LongAdder();
counter.increment();
long sum = counter.sum();

Semaphore sem = new Semaphore(10);
sem.acquire();
sem.release();
```

## 源码分析

`ReentrantLock` 内部 `Sync extends AQS`，`nonfairTryAcquire` 尝试 CAS 设置 state。  
`ForkJoinPool` 双端队列 `WorkQueue` 支持本线程 LIFO、其他线程 FIFO 偷取。

## 面试常见题目

**1. synchronized 锁升级过程？**

偏向 → 轻量 → 重量。

**2. AQS 原理？**

state + CLH 队列；独占与共享模式。

**3. Fair 和 Nonfair 锁？**

公平锁按队列顺序；非公平允许插队，吞吐更高。

**4. Fork/Join 适用场景？**

可递归拆分 CPU 密集任务。

**5. LongAdder 和 AtomicLong？**

高竞争下 LongAdder 分段求和，读 sum 需合并。
