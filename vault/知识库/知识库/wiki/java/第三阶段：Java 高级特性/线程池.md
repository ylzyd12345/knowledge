# 线程池

> Executor 框架与 ThreadPoolExecutor 参数调优。

本文深入 ThreadPoolExecutor 与 Executor 框架。Fork/Join 见并发编程深入；Spring `@Async` 见 Spring 专题。

---

## 概念定义

**线程池**复用线程、控制并发度、管理任务队列，避免频繁创建销毁线程的开销。  
`Executor` 接口：`void execute(Runnable)`；`ExecutorService` 扩展提交、关闭、Future。

---

## 核心原理

### 1. ThreadPoolExecutor 核心参数

| 参数 | 含义 |
|------|------|
| `corePoolSize` | 核心线程数 |
| `maximumPoolSize` | 最大线程数 |
| `keepAliveTime` | 非核心线程空闲存活时间 |
| `workQueue` | 任务队列 |
| `threadFactory` | 线程工厂 |
| `rejectedExecutionHandler` | 拒绝策略 |

### 2. 任务提交流程

1. 线程数 < core → 新建核心线程  
2. 否则入队（队列未满）  
3. 队列满且线程数 < max → 新建非核心线程  
4. 否则执行拒绝策略

### 3. 常见队列

- `LinkedBlockingQueue`：无界（慎用，可能 OOM）
- `ArrayBlockingQueue`：有界数组队列
- `SynchronousQueue`：不存储，直接交接（如 `Executors.newCachedThreadPool`）

### 4. 拒绝策略

- `AbortPolicy`：抛异常（默认）
- `CallerRunsPolicy`：调用者线程执行
- `DiscardPolicy` / `DiscardOldestPolicy`

### 5. 工厂方法

`Executors` 提供固定、缓存、单线程池；阿里规范建议显式 `ThreadPoolExecutor` 配置有界队列与命名线程工厂。

## 实际应用

```java
ThreadPoolExecutor executor = new ThreadPoolExecutor(
    4, 8, 60, TimeUnit.SECONDS,
    new ArrayBlockingQueue<>(100),
    new ThreadFactoryBuilder().setNameFormat("biz-%d").build(),
    new ThreadPoolExecutor.CallerRunsPolicy()
);

executor.execute(() -> doWork());
Future<String> future = executor.submit(() -> "ok");
executor.shutdown();
executor.awaitTermination(30, TimeUnit.SECONDS);
```

**调优思路**：CPU 密集 ≈ 核心数+1；IO 密集可更大；队列大小与拒绝策略须与业务 SLA 匹配。

## 源码分析

`ThreadPoolExecutor.execute` 核心逻辑（概念）：

```java
if (workerCount < corePoolSize) { addWorker(command, true); }
else if (isRunning && workQueue.offer(command)) { /* double-check */ }
else if (!addWorker(command, false)) reject(command);
```

`Worker` 继承 `AQS`，实现可重入执行任务循环（详见并发编程深入）。

## 面试常见题目

**1. 线程池七大参数？**

见上表。

**2. 任务执行流程？**

核心线程 → 队列 → 扩展线程 → 拒绝。

**3. 为何不用 Executors 创建？**

`FixedThreadPool`/`CachedThreadPool` 可能无界队列或无限线程导致 OOM。

**4. 如何设置线程数？**

CPU：`N+1`；IO：`2N` 或按等待时间公式；须压测验证。

**5. shutdown 和 shutdownNow？**

前者温和关闭；后者尝试中断并返回未执行任务列表。

**6. 线程池异常如何处理？**

`submit` 通过 `Future.get` 获取；`execute` 须自定义 `ThreadFactory` 或 `afterExecute`。
