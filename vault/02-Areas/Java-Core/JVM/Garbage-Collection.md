# 垃圾回收（GC）

> 可达性分析、GC 算法与常用收集器。

本文讲解 GC 核心算法与主流收集器。调优参数与工具见 JVM 性能调优；内存区域见 JVM 内存模型专题。

---

## 概念定义

**垃圾回收（GC）** 自动识别并回收不再使用的对象，释放堆内存。判断对象是否存活主要依据**可达性分析**：从 GC Roots 不可达的对象可被回收。

**GC Roots** 包括：栈中引用、静态字段、JNI 引用、同步锁持有对象等。

---

## 核心原理

### 1. 引用类型

| 类型 | 回收时机 |
|------|----------|
| 强引用 | 不回收直到不可达 |
| 软引用 | OOM 前清理，适合缓存 |
| 弱引用 | 下次 GC 清理，`WeakHashMap` |
| 虚引用 | 跟踪对象回收，堆外内存管理 |

### 2. GC 算法

| 算法 | 思想 | 缺点 |
|------|------|------|
| 标记-清除 | 标记存活，清除其余 | 碎片 |
| 复制 | 分两块，复制存活 | 空间减半 |
| 标记-整理 | 标记后移动压缩 | 移动成本 |
| 分代 | 年轻代复制、老年代整理 | 现代默认策略 |

### 3. 常用收集器

| 收集器 | 区域 | 特点 |
|--------|------|------|
| Serial | 单线程 | 客户端、小堆 |
| Parallel | 多线程吞吐 | 默认吞吐导向 |
| CMS | 老年代 | 并发标记清除，碎片与浮动垃圾 |
| G1 | 全堆分区 | 可预测停顿，JDK9+ 默认 |
| ZGC / Shenandoah | 低延迟 | 大堆、毫秒级停顿目标 |

### 4. Minor GC 与 Full GC

年轻代满触发 Minor GC；老年代不足、元空间、System.gc 等可能触发 Full GC（停顿通常更长）。

---

## 实际应用

```bash
# G1 与 GC 日志
java -XX:+UseG1GC -Xlog:gc*:file=gc.log -jar app.jar
```

避免内存泄漏：关闭流、移除监听器、ThreadLocal `remove()`、弱引用缓存配合。

---

## 源码分析

`Object.finalize()` 曾用于复活对象（不推荐）；现代 GC 不依赖 finalize。  
G1 将堆划分为 Region，优先回收垃圾最多的 Region（Mixed GC）。

## 面试常见题目

**1. 如何判断对象可回收？**

可达性分析，从 GC Roots 不可达。

**2. 四种引用？**

见上表。

**3. G1 与 CMS 区别？**

G1 分区、可设停顿目标；CMS 老年代并发清除有碎片。

**4. Minor GC 和 Full GC？**

年轻代 vs 整堆/元空间等全局回收。

**5. 内存泄漏与内存溢出？**

泄漏：对象无法回收但仍被引用；溢出：无法分配新内存。

**6. 安全点与安全区域？**

线程须在安全点才能进入 GC；安全区域处理 sleep 线程。
