针对本地开发环境，我们需要从"企业级生产配置"切换到"轻量级、快速启动、资源友好"的模式。以下是专为本地开发优化的 Docker Compose 配置方案。

## 🖥️ 本地开发环境 Docker Compose 配置

### 核心设计原则

1. **最小化依赖**：只启动本地开发必需的组件
2. **资源友好**：降低内存和CPU占用
3. **端口清晰**：避免与本地其他服务冲突
4. **数据持久化**：保留本地数据，避免重复初始化
5. **快速启动**：优化启动顺序和健康检查

### docker-compose.yml（本地开发版）

```yaml
version: '3.8'

networks:
  dev-network:
    driver: bridge

services:
  # ============================================
  # 1. 基础服务（最小依赖）
  # ============================================

  # 1.1 MySQL（开发库）
  mysql:
    image: mysql:8.0
    container_name: dev-mysql
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: microservice_dev
      MYSQL_USER: dev_user
      MYSQL_PASSWORD: dev_pass
    ports:
      - "3306:3306"
    volumes:
      - ./data/mysql:/var/lib/mysql
      - ./init-scripts:/docker-entrypoint-initdb.d
    command: 
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_unicode_ci
      - --innodb_buffer_pool_size=256M
      - --max_connections=100
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-proot123"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - dev-network
    mem_limit: 512m

  # 1.2 Redis（缓存）
  redis:
    image: redis:7.0-alpine
    container_name: dev-redis
    ports:
      - "6379:6379"
    volumes:
      - ./data/redis:/data
    command: redis-server --appendonly yes --maxmemory 256mb
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - dev-network
    mem_limit: 256m

  # 1.3 RabbitMQ（消息队列）
  rabbitmq:
    image: rabbitmq:3.12-management-alpine
    container_name: dev-rabbitmq
    environment:
      RABBITMQ_DEFAULT_USER: admin
      RABBITMQ_DEFAULT_PASS: admin123
    ports:
      - "5672:5672"
      - "15672:15672"
    volumes:
      - ./data/rabbitmq:/var/lib/rabbitmq
    healthcheck:
      test: ["CMD", "rabbitmq-diagnostics", "-q", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks:
      - dev-network
    mem_limit: 256m

  # ============================================
  # 2. 微服务治理
  # ============================================

  # 2.1 Nacos（注册中心 + 配置中心）
  nacos:
    image: nacos/nacos-server:v2.2.3
    container_name: dev-nacos
    environment:
      MODE: standalone
      PREFER_HOST_MODE: hostname
      # 使用内置 Derby，简化部署（本地开发不依赖外部MySQL）
      SPRING_DATASOURCE_PLATFORM: derby
      JVM_XMS: 256m
      JVM_XMX: 256m
    ports:
      - "8848:8848"
      - "9848:9848"
    volumes:
      - ./data/nacos/logs:/home/nacos/logs
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8848/nacos/v1/console/health/readiness"]
      interval: 30s
      timeout: 10s
      retries: 3
    networks:
      - dev-network
    mem_limit: 512m

  # 2.2 Sentinel Dashboard（流量控制）
  sentinel:
    image: bladex/sentinel-dashboard:1.8.6
    container_name: dev-sentinel
    ports:
      - "8858:8858"
    environment:
      JAVA_OPTS: "-Dserver.port=8858 -Dcsp.sentinel.dashboard.server=localhost:8858 -Dproject.name=sentinel-dashboard -Xmx256m"
    networks:
      - dev-network
    mem_limit: 256m

  # ============================================
  # 3. 可观测性（轻量级）
  # ============================================

  # 3.1 SkyWalking OAP（链路追踪）
  skywalking-oap:
    image: apache/skywalking-oap-server:9.7.0
    container_name: dev-skywalking-oap
    environment:
      SW_STORAGE: h2  # 本地开发用H2内存数据库，避免ES资源占用
      SW_AGENT_COLLECTOR_BACKEND_SERVICES: oap:11800
      JAVA_OPTS: "-Xmx512m"
    ports:
      - "11800:11800"
      - "12800:12800"
    networks:
      - dev-network
    mem_limit: 512m

  # 3.2 SkyWalking UI
  skywalking-ui:
    image: apache/skywalking-ui:9.7.0
    container_name: dev-skywalking-ui
    environment:
      SW_OAP_ADDRESS: http://skywalking-oap:12800
    ports:
      - "8080:8080"
    depends_on:
      - skywalking-oap
    networks:
      - dev-network
    mem_limit: 256m

  # 3.3 Prometheus + Grafana（指标监控）
  prometheus:
    image: prom/prometheus:v2.45.0
    container_name: dev-prometheus
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus/prometheus.yml:/etc/prometheus/prometheus.yml
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.path=/prometheus'
      - '--storage.tsdb.retention.time=7d'
    networks:
      - dev-network
    mem_limit: 256m

  grafana:
    image: grafana/grafana:10.2.0
    container_name: dev-grafana
    ports:
      - "3000:3000"
    environment:
      GF_SECURITY_ADMIN_USER: admin
      GF_SECURITY_ADMIN_PASSWORD: admin
    volumes:
      - ./data/grafana:/var/lib/grafana
    depends_on:
      - prometheus
    networks:
      - dev-network
    mem_limit: 256m
```

| 组件                | 端口                        | 访问地址                                           | 默认账号/密码           |
|:----------------- |:------------------------- |:---------------------------------------------- |:----------------- |
| **MySQL**         | 3306                      | `jdbc:mysql://localhost:3306/microservice_dev` | root/root123      |
| **Redis**         | 6379                      | `redis://localhost:6379`                       | 无密码               |
| **RabbitMQ**      | 5672 (通信)<br>15672 (管理)   | http://localhost:15672                         | admin/admin123    |

| **Sentinel**      | 8858                      | http://localhost:8858                          | sentinel/sentinel |
| **SkyWalking UI** | 8080                      | http://localhost:8080                          | 无登录               |
| **Prometheus**    | 9090                      | http://localhost:9090                          | 无登录               |
| **Grafana**       | 3000                      | http://localhost:3000                          | admin/admin       |

## 🚀 启动命令

```bash
# 1. 创建必要目录
mkdir -p data/mysql data/redis data/rabbitmq data/nacos/logs data/grafana init-scripts prometheus

# 2. 创建 Prometheus 配置文件（可选）
cat > prometheus/prometheus.yml <<EOF
global:
  scrape_interval: 15s
scrape_configs:
  - job_name: 'spring-boot'
    metrics_path: '/actuator/prometheus'
    static_configs:
      - targets: ['host.docker.internal:8081']  # 本地微服务
EOF

# 3. 启动所有服务
docker-compose up -d

# 4. 查看启动状态
docker-compose ps

# 5. 查看日志
docker-compose logs -f nacos mysql
```

        server-addr: localhost:8848

## 💡 本地开发最佳实践

1. **使用 host.docker.internal**：在微服务代码中连接容器服务时，用 `host.docker.internal` 代替 `localhost`（Windows/Mac），Linux 需用 `172.17.0.1`。

2. **配置热加载**：利用 Nacos 配置中心，修改配置后微服务无需重启即可生效。

3. **断点调试**：微服务在 IDEA 中本地启动，连接 Docker 容器中的基础组件（MySQL、Redis 等），端口映射到宿主机即可。

4. **数据初始化**：将初始化 SQL 脚本放在 `init-scripts/` 目录，MySQL 启动时会自动执行。

5. **清理数据**：需要重置环境时，删除 `./data/` 目录并重新启动：
   
   ```bash
   docker-compose down -v
   rm -rf ./data
   docker-compose up -d
   ```

6. **按需启动**：如果不需要某些组件，可以在 `docker-compose.yml` 中注释掉对应的服务：
   
   ```bash
   # 只启动核心组件（MySQL + Redis + Nacos）
   docker-compose up -d mysql redis nacos
   ```

## 🔧 常见问题解决

| 问题             | 解决方案                               |
|:-------------- |:---------------------------------- |
| **端口冲突**       | 修改 `ports` 中的宿主机端口，如 `"3307:3306"` |
| **容器启动失败**     | 查看日志：`docker-compose logs [服务名]`   |
| **数据残留**       | 完全清理：`docker-compose down -v`      |
| **内存不足**       | 调小 `mem_limit` 或关闭不需要的服务           |
| **Nacos 无法启动** | 检查 `8848` 和 `9848` 端口是否都被占用        |
