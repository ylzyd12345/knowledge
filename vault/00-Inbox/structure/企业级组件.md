## ⚠️ 不适合纯 Docker 部署的组件

以下组件通常**不推荐**单独用 Docker 部署，或因设计原因无法直接容器化：

| 组件                            | 不推荐原因              | 推荐替代方案                |
|:----------------------------- |:------------------ |:--------------------- |
| **ShardingSphere**（分库分表）      | 应用层 JAR 包依赖，不是独立服务 | 直接作为依赖集成到业务微服务中       |
| **Spring Cloud LoadBalancer** | 客户端负载均衡器，非独立服务     | 集成在微服务代码中             |
| **OpenFeign**                 | 声明式 HTTP 客户端，非独立服务 | 集成在微服务代码中             |
| **Caffeine**                  | 本地缓存库，非独立服务        | 集成在微服务代码中             |
| **HikariCP / Druid**          | 数据库连接池，非独立服务       | 集成在微服务代码中             |
| **F5 / 硬件负载均衡器**              | 物理设备               | 云厂商 LB 或 Nginx 替代     |
| **Kubernetes 自身**             | 容器编排平台，非 Docker 容器 | 部署在物理机/VM，通过容器运行时管理容器 |

## 📦 总结：Docker 部署的企业级关注重点

| 关注点           | 关键实践                                                                   |
|:------------- |:---------------------------------------------------------------------- |
| **数据持久化**     | 所有有状态组件（MySQL、Redis、ES、MinIO）**必须**挂载宿主机目录或使用网络存储（NFS/Ceph）            |
| **健康检查与启动顺序** | 配置 `healthcheck`，通过 `depends_on` 的 `condition: service_healthy` 控制启动顺序 |
| **日志管理**      | 容器内日志输出到 `stdout`，由采集器（Filebeat/Fluentd）统一收集，**避免容器日志无限增长**            |
| **集群通信**      | Nacos 需开放 `8848`（HTTP）和 `9848`（gRPC）端口，否则集群节点无法通信                      |
| **端口暴露**      | 仅对外暴露网关、控制台（Nacos/Kibana/Grafana）等必要端口，内部组件通过 Docker 网络通信              |
| **资源限制**      | 为每个容器设置 `deploy.resources.limits`（CPU/内存），避免资源争抢导致主机崩溃                 |
| **配置管理**      | 使用 **环境变量** 或 **Docker Secret** 管理密码、Key 等敏感信息                         |
